## 1. 项目定位

`rtc-talk-win` 是面向正式交付的 Windows x64 RTC 桌面客户端，不是功能演示、
不是原型拼接、也不是对现有 `client-win` demo 的增量修补。

新工程必须：

- 具备清晰、可替换、可测试的生产模块边界。
- 允许参考 demo 的行为和协议，但不允许照搬 demo 的类结构和耦合方式。
- 将“可编译、可测试、可观测、可安装、可诊断”作为每个模块的完成条件。
- 以服务端协议和真实媒体链路为权威，不假设 UI mock 数据有效。

## 3. 交付边界

### 3.1 一期必须交付

- Windows 10/11 x64 桌面客户端。
- 连接、`session.hello`、入房、离房、断线恢复、顶号和被踢处理。
- 正式 Token 与开发 Token 两种联调方式。
- 音频和视频设备枚举、设备选择、热插拔刷新。
- 麦克风、摄像头、屏幕共享、收听静音及音量控制。
- 本地摄像头预览、远端多路视频、共享画面和 1v1 画中画。
- 宫格、聚焦、仅视频成员、共享布局。
- 成员、角色、音量、主讲人、发言权和排队状态。
- 自由发言、PTT、主持人审核三种对讲模式。
- 主持人授予/收回发言权、全员静音、移出成员、策略修改。
- 连接失败、命令失败、设备失败、媒体失败的可恢复错误处理。
- 媒体统计、当前会话诊断、日志导出。
- 配置持久化。
- Windows 安装包和干净环境运行验证。

### 3.2 明确不在一期

- macOS、Linux、RK3576 客户端。
- 录制、GB28181、E2EE、Simulcast。
- 多人会议室、转写、虚拟背景。
- `call.invite` 呼叫弹窗；一期采用直接入房。
- 自动更新服务。
- 多节点 SFU 调度和超出服务端协议的新媒体能力。

## 4. 功能要求

### 4.1 会话与信令

- FR-SESSION-001：支持 `ws://` 开发环境和 `wss://` 正式环境，TLS 必须校验证书。
- FR-SESSION-002：连接后严格按协议完成 `session.hello`，之后才允许入房。
- FR-SESSION-003：Token 不写入普通配置文件；如需记住登录态，使用 Windows
  Credential Manager 或 DPAPI。
- FR-SESSION-004：断线后在服务端恢复窗口内尝试恢复；过期后回到入房页并明确提示。
- FR-SESSION-005：区分主动离房、网络断开、被踢和账号替换，不得错误自动重连。
- FR-SESSION-006：所有请求具备超时、取消和旧 generation 隔离。

### 4.2 入房与设备

- FR-PREJOIN-001：入房页支持服务地址、用户标识、房间、Token、开发凭证、音频后端、
  音频源、媒体模式、对讲模式、播放音量、麦克风和摄像头选择。
- FR-PREJOIN-002：摄像头和音频设备枚举不得阻塞 UI 线程。
- FR-PREJOIN-003：摄像头可在入房前启动、停止和切换预览。
- FR-PREJOIN-004：设备被占用、权限拒绝或拔插时，界面给出可操作错误，不崩溃。
- FR-PREJOIN-005：设置可持久化，但 Token、密码和 SDP 等敏感内容不得落盘。

### 4.3 房间与成员

- FR-ROOM-001：成员列表、角色、静音、摄像头、共享、发言、音量和排队状态来自真实事件。
- FR-ROOM-002：连接状态、媒体模式、房间人数和会话时长准确显示。
- FR-ROOM-003：成员选择与聚焦状态稳定，不因普通状态更新丢失。
- FR-ROOM-004：房间事件乱序、重复或迟到时，状态收敛到服务端权威值。

### 4.4 音视频

- FR-AV-001：麦克风、摄像头、屏幕共享和收听静音均有明确命令结果和失败回滚。
- FR-AV-002：本地预览与正式发布共享采集能力，但拥有独立生命周期；停止预览不得误停发布。
- FR-AV-003：远端视频按 `mid` 注册，摄像头和共享流可区分，不得串流。
- FR-AV-004：每路只保留最新帧，合并 UI 刷新；队列有上限，不得无限增长。
- FR-AV-005：`media.producer(paused)` 立即清除对应画面；5 秒无帧回收 Surface。
- FR-AV-006：支持宫格、聚焦、1v1 画中画、共享主画面和胶片条。
- FR-AV-007：视频渲染边界可替换为后续 D3D/OpenGL，不影响页面业务代码。

### 4.5 对讲与主持人

- FR-FLOOR-001：PTT 按下申请、松开释放，支持排队、倒计时和 revoke。
- FR-FLOOR-002：本地开麦状态以服务端发言权和命令结果为权威。
- FR-HOST-001：主持人可授予/收回发言权、全员静音、移出成员和修改房间策略。
- FR-HOST-002：策略更新必须局部合并，不得重置未修改字段。

### 4.6 诊断与运维

- FR-DIAG-001：周期性采集真实 `media.stats`，展示 RTT、码率、丢包、设备与链路状态。
- FR-DIAG-002：日志按级别、大小和数量滚动，不记录 Token、密码、完整 SDP。
- FR-DIAG-003：支持导出脱敏诊断包。
- FR-DIAG-004：关键错误带稳定错误码、用户提示和排障详情。
- FR-DIAG-005：预留崩溃转储路径和版本信息。

## 5. 生产架构硬约束

以下规则属于验收门禁，不是建议：

- AR-001：UI 工程不得包含 WebRTC、Media Foundation、asio、nlohmann/json 私有头文件。
- AR-002：页面不得解析协议 JSON，不得直接调用底层媒体对象。
- AR-003：JSON 只允许存在于协议编解码和 C ABI 边界；领域层使用强类型对象。
- AR-004：摄像头、音频、屏幕采集、WebRTC PeerConnection、信令分别有独立接口和 Windows adapter。
- AR-005：业务会话编排不得依赖具体 WebRTC 类；通过注入接口和 Fake 实现测试。
- AR-006：UI 依赖应用服务接口；应用服务依赖领域接口；基础设施实现接口。
- AR-007：不允许新增“万能类”。单个实现文件原则上不超过 600 行，超过必须拆分并记录原因。
- AR-008：所有跨线程回调必须标明线程、生命周期和所有权。
- AR-009：所有资源采用 RAII；关闭顺序必须可重复执行并有测试。
- AR-010：功能代码合并前必须有对应单元测试或集成测试。
- AR-011：不得把 demo 代码直接复制后继续修改；如复用算法，必须迁移到新模块、
  去除旧依赖、补接口和测试后才能通过验收。
- AR-012：所有架构偏离必须形成 ADR，并由用户确认。

## 6. 非功能要求

### 6.1 稳定性

- 30 分钟双人通话、2 小时多人视频无崩溃和持续内存增长。
- 断网 10 秒后能恢复或给出明确失败路径。
- 连续开关摄像头/共享 100 次无死锁、无泄漏、无状态卡死。
- 设备拔插、被占用、权限拒绝不得导致客户端退出。

### 6.2 性能

- UI 主线程单次事件处理目标小于 16ms。
- 远端视频最多同时显示 9 路，按 30fps 刷新目标合并。
- 视频帧队列按流限制为 1 帧最新值，不积压历史帧。
- 启动到可操作入房页目标小于 3 秒，设备枚举异步进行。

### 6.3 安全

- 正式环境必须 WSS。
- Token 只在内存或系统凭证存储中。
- 日志、诊断包和崩溃信息必须脱敏。
- 所有服务端输入做长度、类型和边界校验。

### 6.4 兼容性与可访问性

- Windows 10 22H2、Windows 11 x64。
- 125%、150% DPI 下布局不截断、不重叠。
- 1100x720 最小窗口可用，1440x900 为基准布局。
- 键盘焦点、Tab 顺序、禁用态和错误态可辨识。

## 8. 验收定义

一个模块只有同时满足以下条件才算完成：

1. 代码符合架构硬约束。
2. 单元测试、集成测试和相关回归全部通过。
3. 真实服务链路验证通过。
4. 失败路径、超时和资源释放有验证。
5. 日志、错误码和用户提示完整。
6. 无未处理编译警告、无已知崩溃、无未记录架构债。
7. 文档、接口说明和变更记录同步。
8. 用户按阶段交付清单验收确认。
