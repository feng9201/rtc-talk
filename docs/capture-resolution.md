# 采集分辨率设置

摄像头默认 720P；入房前的连接配置页根据当前摄像头能力列出 720P、1080P
及像素总数最大的有效原生尺寸。最大值与 720P/1080P 重合时合并显示。
切换设备后移除不支持的选项，优先保留原尺寸，否则选列表第一个有效档位。
设备占用导致临时无法枚举能力时，保留同编号、同名称设备最近一次能力。

设置随入房参数传入媒体核心；入房后固定该尺寸，房间设备页只读显示。
入房、重连期间引擎拒绝预览设置命令。离房后可重新选择。
预览时修改尺寸会重新打开本地采集；失败显示错误，不静默改用其他尺寸。
房间内仍可选择其他摄像头，但新摄像头必须支持本次入房确定的尺寸；失败恢复原设备。

能力枚举保留分辨率与帧率组合。以 15 fps 为目标，在选定尺寸的有效模式中选择
最接近的帧率，并保留原始帧率分数；先选择原生媒体类型，再请求 NV12 输出。
驱动协商出的尺寸或格式不符合请求时明确失败，不按错误尺寸读取缓冲区。
若直接转换到 NV12 失败，会重新打开设备并启用 Media Foundation 高级格式转换
再试一次；仍须先选中对应原生模式，禁止从低分辨率放大冒充原生输出。
预览信息显示实际尺寸与帧率。

桌面/窗口有两种设置：

- 1080P：保持比例，缩小至 1920×1080 以内，不放大小画面。
- 原始分辨率：使用所选屏幕/窗口当前实际像素尺寸，不限制为 1080P；宽高对齐偶数。

入房前可设置默认值；房间设备页在未共享时可修改。共享期间 UI 禁用设置，
引擎及采集源均拒绝修改。停止后恢复可选。选择的是策略，因此更换显示器、
系统分辨率或共享窗口大小变化后，会跟随新源尺寸，不沿用旧显示器尺寸。

保存设置会保存摄像头宽高和桌面策略。默认值为摄像头 1280×720、桌面 1080P。

## 验证

自动测试覆盖能力选项、最大值合并、设备切换、保存恢复、入房锁定和共享锁定。
手工短测试不加入房间、不保存图像：

```powershell
.\build\windows-x64\bin\Release\rtcwin_camera_preview_smoke.exe --cycles 1 --hold-ms 200 --width 1280 --height 720
.\build\windows-x64\bin\Release\rtcwin_camera_preview_smoke.exe --cycles 1 --hold-ms 200 --width 1920 --height 1080
.\build\windows-x64\bin\Release\rtcwin_capture_resolution_smoke.exe
```

本机验证：摄像头 720P、1080P 均收到对应尺寸帧；最大 2304×1536 也能收到帧，
该设备最大档实际仅约 2 fps；桌面原始输出 3840×2160、
1080P 输出 1920×1080；本机 H.264 720P、1080P、4K 编解码还原尺寸一致。
最后一项手工工具会给异步编码器短暂预热时间，不作为稳定性测试。

采集尺寸不等于网络发送尺寸。WebRTC 编码适配、码率、SFU 协商和对端能力
仍可能限制最终发送或显示尺寸。本次保留既有 H.264 协商格式和发送码率策略，
未验证跨设备 SFU 的高分辨率端到端传输。
日志中的 `capture size` 为摄像头采集尺寸，`video rtp ... size` 为 SDK 上报
的编码/解码帧尺寸；SDK 尚未上报时为 0。
