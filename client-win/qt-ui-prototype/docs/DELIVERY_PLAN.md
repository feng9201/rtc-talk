# RTC Talk Qt Widgets GUI 分阶段交付计划

> 更新日期：2026-10-23  
> 项目目录：`client-win/qt-ui-prototype`  
> 当前状态：M1–M6 已完成并确认；GUI mock 第一版交付完成。

## 一、交付方式

采用“单模块开发 → 构建验证 → 暂停通知 → 用户确认 → 下一模块”的串行交付方式。

每个模块完成后必须提供：

1. 模块完成情况
2. 修改文件列表
3. 构建结果
4. 可执行验证命令
5. 验收截图路径（涉及视觉的模块）
6. 已知限制
7. 需要确认的验收项

在用户明确确认当前模块之前，不开始下一模块。

## 二、总体目标

第一版交付一个可独立运行、可交互、可用 mock 数据验收的 Qt Widgets 桌面 GUI：

- 参考 `design/video-ui-prototype/index.html`
- 使用 Qt 5.15 Widgets
- 复用项目内 `FramelessWindow`
- 界面层不直接依赖 WebRTC/CoreClient
- 视频渲染保留 `VideoSurface` 替换边界
- 暂不接入真实信令、设备和媒体流

## 四、模块详细验收项

### M1 应用壳与房间页骨架

- 默认启动进入入房页
- 点击入房后切换到房间页
- 离开后回到入房页
- 右上角窗口控制按钮可用
- 无边框窗口可拖动、缩放、最小化和最大化
- 房间页静态布局在 1440×900 和 1100×720 下无遮挡
- `RelWithDebInfo` 构建通过

### M2 视频舞台与布局

- 多人宫格布局正确
- 1v1 显示远端大画面和本地画中画
- 聚焦模式正确
- 屏幕共享显示共享主画面和成员缩略图
- “仅视频成员”过滤有效
- 单击选择、双击聚焦有效
- 提供各场景截图

### M3 房间控制与状态同步

- 麦克风开关状态、图标和文案同步
- 摄像头开关状态同步
- 屏幕共享状态同步
- 收听/静音状态同步
- 设置按钮可打开设置弹窗
- 离开按钮先弹出确认框，确认后才离开
- Toast 正常显示和消失

### M4 右侧面板

- 成员、设备、状态 Tab 可切换
- 成员列表可滚动，当前成员高亮
- 双击成员可聚焦
- 主持人操作菜单仅对非本人显示
- 全员静音可执行
- 麦克风和系统音频源互斥
- 设备下拉框、刷新、诊断和音量控件可用
- 状态页显示连接、媒体模式、音频源、设备和统计信息

### M5 弹窗、诊断与视觉收口

- 设置弹窗控件与当前状态同步
- 诊断抽屉从右侧覆盖，遮罩可关闭
- 弹窗和抽屉不会互相错误遮挡
- QSS 覆盖房间页、侧栏、弹窗和诊断页
- 下拉框箭头可见
- `Pill`、`SegmentedControl` 的 hover/checked/disabled 状态完整
- 主要颜色、间距和层级与 HTML 原型一致

### M6 场景验收与交接

- `--scenario prejoin|multi|one|sharing|devices|diagnostics` 可用
- `--smoke-seconds` 到期可退出
- `--screenshot` 可生成截图
- 六种场景截图通过检查
- 125% 和 150% Windows 缩放下布局可用
- README 补充运行、验收和后续接入说明

## 五、范围边界

本计划仅覆盖 GUI 第一版，不包含：

- libwebrtc 接入
- CoreClient 适配
- 信令和房间协议联调
- 真实摄像头、麦克风、扬声器设备枚举
- 真实 `getStats` 数据接入
- OpenGL/D3D 视频渲染实现

GUI 第一版完成后，真实媒体和业务接入作为后续独立阶段评估。
