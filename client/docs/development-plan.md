# 面向生产的开发计划

## 1. 目标与完成定义

最终交付包括架构方案、真实目录、API 定义、UI 架构和完整源码/构建/测试/部署说明。
先设计，再实现可扩展的最小纵向产品，再补齐完整业务和生产可靠性。
“编译通过”“fake ADM 互通”“UI 截图成功”均不能单独视为产品完成。
旧 RK 音频计划保留作历史记录；本计划替代其“RK 一期不接视频”的范围。

本项目不是要求立即修改服务端，客户端能力不能超出服务器真实实现。
发现服务器能力缺口先用契约测试说明，再决定最小兼容改动；不伤害现有房间与用户。

## 2. 阶段、依赖和交付

| 阶段 | 交付 | 出口标准 | 初步工作量* |
|---|---|---|---|
| A0 架构/基线 | 本组文档、独立 worktree/分支、依赖矩阵/风险表 | 边界、线程、所有权、API、UI 和投产门槛可评审 | 1–2 天 |
| A1 可测内核 | Domain 状态/权限 gate、generation、资源预算、有界帧队列、单元测试 | host 无硬件运行，Release 仍执行断言测试，无旧帧/漏音逻辑缺口 | 2–3 天 |
| A2 信令/音频 | WS/WSS、RPC、hello/join/leave、SFU Opus、CLI、log-cpp | 临时房间双 RK + Windows 互通；严格 TLS 反例通过；真实声卡待专项验收 | 3–5 天 |
| A3 RK 视频纵向 | MPP factory、NativeFrame、track mapping、Wayland、单路收视 | Windows 推 H264+Opus → RK 音视频播放，RK 上行仅 Opus；无空 codec 崩溃 | 5–8 天 |
| A4 M1 UI/打包 | Qt 页面/Store/Presenter、设备选择、安装包/诊断 | 全流程不依赖 CLI 手动命令；单路可用、有界关闭、可部署回滚 | 3–5 天 |
| A5 业务完整 | PTT/floor、主持、呼叫、角色、房间策略/状态恢复 | 全量契约/竞争时序/权限拒绝用例；所有命令有最终结果 | 4–7 天 |
| A6 可靠性/容量 | 重连/ICE、关键帧恢复、过载准入、多路、长期资源验证 | 定义故障均有可解释状态/恢复上限；测出批准容量，不拍脑袋承诺 9 路 | 4–7 天 |
| A7 生产加固 | 正式凭证/CA/TURN、SBOM/许可、CI、supervisor、运维/回滚 | 安全/互通/稳定性/安装验收全部通过，无已知阻断缺陷 | 3–5 天 |

* 单工程师有效工作日的初估，不含外部身份/证书部署、硬件固件修复和等待用户联调时间。
总计约 25–42 工作日；A2–A4 是关键路径，得到首个真板视频闭环后重新估算，不承诺该估算即交付日期。
M1 = A1–A4 通过；GA = A0–A7 全部通过。P2P/H265/更多芯片是 GA 后独立扩展，除非另行调整范围。

## 3. 施工顺序与最小可用定义

1. 固定 docs 和模块 ports，内核测试不依赖私有库。
2. 固定 SDK/MPP/Wayland/log-cpp 版本，记录来源。私有库任何实际问题先向用户求助。
3. 音频上行 + H264 下行真实协商测试优先于美化 UI。复现旧版本“视频 m-line + 空 codec”崩溃，
   新版本同场景不得崩溃；不要用删除视频或假解码通过测试。
4. 在 WebRTC decoder seam 输出真实 NV12 lease，经 SDK 调度到 sink 后再渲染。
5. 验证 paused/screen/resize/关闭时 compositor 在途帧，之后才扩展成员选择和 UI。
6. CLI 和 Qt 共用同一个 engine，诊断路径不能另造一套行为。
7. 纯模拟模式只存在测试 target；产品缺失媒体依赖时构建或启动明确失败，不以 NullMedia 假装成功。

M1 必须能：启动→认证→选择房间→静音入房→播放远端 Opus+H264→授权后发送麦克风→关麦→离房/关闭；
同时有结构化错误、有界日志、基本重连状态、单路视频资源上限和可追溯的构建制品。
M1 不以裸 token 文本框 + shell 启动流程作为最终生产登录 UI。

## 4. 验证矩阵

### 内核与协议（每次变更）

- generation 递增/旧结果拒绝；mute 所有分支；授权应答迟到；PTT 撤销/松手时序。
- 命令队列满、RPC timeout/未知 id/重复 response、双向同 id、非法 JSON/字段/超大消息。
- 会话恢复成功/过期/踢出/主动退出；路由状态回滚；所有 accepted 操作恰好一个 result。
- latest mailbox 覆盖/关闭/并发/重入析构；committed lease 只能由 release/连接销毁归还。
- 视频预算溢出、尺寸/stride/内存大小校验、超大 AU、资源不足与池 generation 延寿。

### 媒体与真实硬件

- RK↔RK Opus、RK↔Windows Opus+H264，房间 audio-only/混合/video paused/camera+screen。
- 使用高动态 PT 的协商，非 102 仍可收 H264；不支持编码明确拒绝而音频不崩溃。
- 首帧、关键帧丢失、PLI 恢复、丢包/乱序/突发、屏幕低帧率、分辨率切换、源结束/重建。
- 真实声卡录播、采样率转换、半双工/全双工、AEC/NS/AGC、回声和削波；需用户听音配合。
- Wayland 不可用/子连接断开/无显示器/隐藏恢复；整台 Weston 重启只在专用安全环境测试。
- 每次 100 次 join/leave、100 次流增删、并发关闭；统计 RSS/FD/线程/MPP lease 稳定回收。

### 生产准入目标（待实测校准但不能静默降低）

- 基准条件：有线 LAN、无人工丢包、1 路 H264 1080p30 + Opus、指定显示/声卡/BSP。
- 30 次入房首视频帧延迟 P95 ≤3s（从完成入房起）；交互式音频端到端 P95 ≤300ms。
- 音画偏差绝对值 P95 ≤150ms；用时间码/音调同源测试并记录方法，不能从 stats 猜。
- 稳态 30 分钟 RSS/FD/线程无持续增长；8h 稳定性 + 24h 试运行作为 GA 门槛，时间需明确安排。
- 分辨率/并发容量以实测矩阵发布；CPU/RSS/VDPU/输入码率都纳入，不只看像素吞吐。
- 无永久黑屏/死锁；网络恢复按 TTL 与退避完成或明确退出；不能靠无限重试掩盖故障。
- 关麦安全 gate 10ms 帧边界内生效，以编码前测量验证；不承诺已在网络中的旧包消失。
- TLS 自签/过期/错域/不可信 CA 拒绝；过期或越权 JWT、非法 rooms、伪造命令不越权。
- 包校验、离线依赖、最小权限运行、磁盘满/只读配置、日志轮转、停止与回滚均验证。

长时间与破坏性故障测试不在共享开发服务器/业务板上偷偷执行。优先在 `/tmp` 短测采证，
故障注入和稳定性测试记录窗口、房间、进程、回收操作与结果，避免干扰现有用户。

## 5. CI、交付与运维

- PR：格式/编译/unit/contract；host sanitizers；不携带凭证和本地 build 目录。
- RK job：固定 SDK + vcpkg 缓存，交叉编译 + ELF/符号/RPATH/依赖检查，输出 manifest 与符号。
- 硬件 job：受控 runner/板端临时目录，测试后只回收本次进程和目录，导出脱敏报告。
- release：版本目录、可核验 SHA256、SBOM/第三方许可、配置 schema、操作说明、已知限制。
- 上线前确认正式身份服务、WSS 域名/CA、TURN、设备权限组、init/supervisor、时间同步、存储预算。
- 停止只针对本应用 PID/服务，不使用 killall，不重启业务服务。回滚不覆盖系统共享库。

## 6. 风险登记与应对

| 风险 | 处理/验证 | 是否阻断 GA |
|---|---|---|
| M146 构建关闭内置 H264 | 外部 factory + 真机协商，不先重编整个 SDK | 是 |
| MPP buffer 生命周期跨 decoder/renderer | RAII lease、池 generation、release 测试 | 是 |
| sbdc 私有封装/API 版本差异 | 固定源码，先请用户确认具体问题再处理 | 是 |
| 超预算远端视频已被服务器自动消费 | 验证 m-line 拒绝语义；必要时提出受控服务端订阅扩展 | 多路/资源安全是 |
| Weston 层级/热插拔 BSP 特性 | 使用现行代码、协议能力探测、专用环境回归 | 是 |
| 低 fps 被误判解码挂死 | 结合输入/paused/progress 状态，不盲目 1 秒 reset | 是 |
| 真实 AEC/设备映射未验收 | 静音默认、用户协助听音、录播基准 | 是 |
| 当前仅开发 WS/token | 正式身份/CA/TURN 上线依赖表，不宣称客户端单独解决 | 是 |
| sdk/许可/codec 商用授权 | 固定制品来源、许可证及发行授权确认 | 是 |

## 7. 不允许的“完成替代品”

不以假帧/假 RPC 代替真实硬解，不以空视频工厂拒绝所有视频而声称支持视频，
不以源码 skeleton 或输出架构图代替完整代码，不以 /tmp 短测代替长期可靠性结论。
每个阶段更新 [status](status.md) 的源码、命令、证据和未完成项，只有出口标准通过才打勾。
